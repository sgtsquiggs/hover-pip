# AGENTS.md

Context for coding agents working on Hover PiP. `CLAUDE.md` imports this file,
so shared guidance goes here and only Claude-specific notes go in `CLAUDE.md`.

## What this is

Hover PiP is a Manifest V3 extension for Chromium browsers that ports Firefox's
Picture-in-Picture toggle. Hover a video at least 45 s long and 140×140 px and
a button appears on its right edge; clicking it opens Picture-in-Picture.
**Alt+P** toggles PiP on the most prominent video in any frame. It's plain
JavaScript: no build step and no runtime dependencies. MPL-2.0, at
<https://github.com/sgtsquiggs/hover-pip>.

## Layout

- `extension/` is the extension as shipped:
  - `logic.js`: pure decision logic, shared by the content script, the service
    worker and `node:test`.
  - `toggle-styles.js`: Firefox's `pipToggle.css`, as a string.
  - `content.js`: hover detection, the overlay, and entering PiP. It loads after
    the other two, in one isolated world.
  - `background.js`: Alt+P across frames, and injecting the content scripts into
    open tabs on install and update.
  - `icons/`: generated by `npm run icons`; don't edit by hand.
- `vendor/firefox-156.0.1/`: verbatim Firefox sources the port follows. Don't edit.
- `test/`:
  - `unit/`: `node:test`.
  - `e2e/`: Playwright, headed under Xvfb, with pages in `fixtures/`.
  - `smoke/`: live sites, opt-in.
  - `visual/parity.js`: screenshots compared against Firefox.
- `scripts/`: `package.js`, `sign.js`, `bump-version.js`, `icons.js`, and
  `demo/` (the recording behind the README and release media).
- `media/`: README and release-page assets (`media/store/` keeps its old
  name). `media/icon.svg` is the icon source.

## Commands

```sh
npm test              # unit tests
npm run test:e2e      # e2e: headed Chromium under xvfb-run; needs ffmpeg, Xvfb, uv
npm run test:smoke    # live sites; never in CI
npm run package       # dist/hover-pip-<version>.zip
npm run sign -- <dir> <key.pem>  # dist/hover-pip-<version>.crx, update.xml
npm run bump -- patch # or minor, major, x.y.z: sets the manifest version
npm run icons         # media/icon.svg -> extension/icons/*.png
npm run demo && npm run demo:media   # re-record the demo, regenerate media/
```

- The e2e suite unsets `WAYLAND_DISPLAY` and runs Chromium with
  `--ozone-platform=x11` on one worker, because the Alt+P tests send a real
  XTest key event to the focused window.
- `CHROMIUM_PATH` selects another Chromium build. The smoke tests default to
  `/usr/bin/chromium`, which has the proprietary codecs Playwright's build lacks.
- `EXTENSION_DIR` tests another copy of the extension. CI uses it to run the e2e
  suite against the unzipped package.

## Workflow

- **Every change is a pull request from a branch.** A ruleset on `main` requires
  a PR, and the `test` check must pass on a branch that's up to date with `main`.
  Merges are squash-only with linear history; force pushes and deletion are
  blocked, and nobody can bypass the rules. Never push to `main`.
- Merge only with the maintainer's go-ahead.
- Commit subjects use Conventional Commits (`fix:`, `feat:`, `test:`, `docs:`,
  `build:`, `ci:`, `chore:`). The squash commit takes the PR title and body.
- **No AI attribution trailers** (such as `Co-Authored-By`) in commits or PR
  bodies. Authorship is credited in the README and `package.json`.
- Before pushing, run `npm test` and `npm run test:e2e`. A behaviour fix comes
  with an e2e test that fails without it.
- Releases follow the README's Release section: a version bump PR, then a
  `vX.Y.Z` tag on `main`, which the Release workflow signs and publishes.
  Push a tag only with the maintainer's go-ahead; a release is public at once.

## Easy to get wrong

- The content script runs in an isolated world in every frame, but it shares the
  DOM with the page:
  - build DOM with `createElement`, never `innerHTML` (Trusted Types);
  - keep the overlay host's `!important` styles;
  - ignore events whose `isTrusted` is false.
- Every event entry point goes through `guarded()`, so a page that breaks an
  assumption gets one warning instead of an error on every mouse move. Wrap new
  handlers the same way.
- After an update or uninstall, the old content script lives on in open tabs. It
  notices `chrome.runtime?.id` is gone and calls `retire()`. Listeners use the
  shared `AbortController` signal so `retire()` can remove them; any new
  listener or timer must be covered by `retire()` too.
- The e2e browser profile turns Developer mode on. Without it, Chromium disables
  an unpacked extension that reloads.
- Smoke-test failures are often the harness, not the extension: lazy players,
  consent walls, offline channels. Look at the failure screenshot first.
- The product is **Hover PiP**. Firefox appears only as attribution (MPL
  headers, credits, `vendor/`). Never use Firefox or Chrome as a brand name;
  both are trademarks.
- The `HOVER_PIP_CRX_KEY` secret fixes the extension ID,
  `iklppbfbkekmbjalepgliappemgchmij`. Never replace the key or change the
  manifest's `update_url`: installed copies would stop updating.
- Thresholds and behaviour follow Firefox 156. When porting more, cite the
  Firefox source file. The README lists the deliberate differences.
